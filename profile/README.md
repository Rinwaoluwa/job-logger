# Profile knowledge base

This directory is the **only** source of truth the AI pipeline uses to
write résumé bullets, cover letters, application answers, and interview
prep. Nothing here is generated by the app — you edit these files by hand
(or dictate answers in a chat interview that gets written back into them).
Every claim in a generated document must trace back to a story or metric
id defined here; anything the model adds beyond this content gets flagged
as `inferred` and shown in a review panel before it reaches an exported
document.

Run `npm run profile:check` any time to see a summary and a list of
warnings (draft stories, unverified metrics, unanswered `<ask>`
placeholders, duplicate ids, broken references).

## Files

- `facts.md` — header/contact info, target roles and locations, work
  authorization, the *true* employment timeline (including how to talk
  about overlapping roles), education, and a global "do not claim" list.
- `skills.md` — a skill inventory table with a proficiency level and which
  roles you actually used each skill in.
- `behavioral.md` — general behavioral stories (conflict, failure,
  leadership, etc.) that aren't tied to a specific technical role.
- `roles/NN-slug.md` — one file per job, in résumé order. Each has header
  fields, free-text context, a bullet list of what was built, the
  technologies really used, a **verified metrics** list, and full STAR
  stories.
- `projects.md` — personal and side projects, one `### [proj-slug] Title`
  block each with labelled fields (Status, Dates, Link, Stack, What it is,
  What I built, Decisions / trade-offs, Outcome, Use). Projects never go on
  the résumé; a verified project with `Use: prose` is offered to cover
  letters, answers and interview prep as background, `Use: none` keeps it
  on the Profile tab only. Optional file.

## Conventions the parser depends on

**Role file header** — plain `key: value` lines at the very top, ending at
the first blank line or `#`/`##` heading:

```
id: northwind
company: Northwind
title: Senior Full Stack Developer
dates: April 2026 – Present
location: Vancouver, British Columbia (hybrid)
employment_type: full-time
engagement: Full-time, 40 hrs/week
status: verified            # verified | draft — draft means AI-drafted, unconfirmed
resume_order: 1
show_on_resume: yes         # "no" excludes this role entirely from résumés
```

`engagement` is optional and is printed verbatim after the title on every
résumé ("BrightPay — Fullstack Engineer (Full-time, 40 hrs/week)"), so
overlapping roles read honestly. Keep it short and do not put a `#` comment
on that line; everything after the colon is the label. A revise instruction
can override or remove it on one résumé.

**Sections** — recognized `## ` headings (anything else triggers a
"unknown section heading" warning): `Company & product context`,
`Team & my role`, `What I built`, `Technologies actually used`,
`Verified metrics`, `Stories`, `Do NOT claim`, `Notes`.

A `Technologies actually used` line may carry a note in parentheses
(`React (legacy apps alongside the Nuxt work, not the main build)`). The
note reaches the models as written, and a limiting note is what makes the
technology eligible for a reframe: when a posting leads with it, the
planner may present the role's frontend in that technology, each such
bullet review-gated with the real-stack wording as its fallback. A
technology not on the list is never reframed; it can only arrive as a
gap fill.

**Stories** — `### [role-sN] Title`, with labeled fields below it. A
continuation line (no `**Label:**` prefix) is appended to whichever label
came before it:

```
### [northwind-s1] Workpaper sync and multi-level approval
**Status:** verified
**Competencies:** ownership, workflow design, full-stack delivery
**Situation:** Auditors were preparing workpapers and reports across
scattered systems, which made the process fragmented and error-prone.
**What I did:** ...
**Decisions / trade-offs:** ...
**Outcome:** ...
**Interview version:** <60-90 second spoken version — used for cover letters, answers and interview prep, not for résumé bullets>
**Metrics:** northwind-m1, northwind-m2      (optional — only ids from this role's Verified metrics)
```

**Metrics** — one per line under `## Verified metrics`:

```
- [northwind-m1] Auditors adopted the workflow with positive feedback | verified: yes | resume: yes
```

If a role genuinely has no verifiable numbers, write `- none — do not put
numbers on this role` instead of inventing metrics. Until you flip
`verified: no` to `verified: yes`, the pipeline treats that number as
unavailable — it will not appear in a résumé bullet unmarked.

**Technologies** — `- name (how it was used)`; the parenthetical is
optional.

**id scheme** — `<role-id>-s<N>` for stories, `<role-id>-m<N>` for
metrics, `gen-s<N>` for behavioral stories (auto-numbered by heading order
in `behavioral.md`). Ids must be unique across the whole profile.

## Status field meaning

- `verified` — you wrote this, or confirmed an AI draft is accurate. Safe
  to use freely, including any of its metrics once you've flipped them to
  `verified: yes`.
- `draft` — carried over from an old AI-generated interview-prep draft.
  The pipeline prefers verified content and will only use a draft story's
  non-numeric shape (situation/actions), never its numbers, until you
  confirm it and flip the status.

## Editing workflow

1. Edit the relevant `.md` file.
2. Run `npm run profile:check` (or just hit the app — the loader caches by
   file mtime, so a save is picked up on the very next request).
3. Once a role's stories are confirmed accurate, flip `status: draft` to
   `status: verified` and flip any correct metrics to `verified: yes`.
